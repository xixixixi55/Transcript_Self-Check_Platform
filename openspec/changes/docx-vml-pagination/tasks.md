# docx-vml-pagination：模板 VML 与附件分页修复

## 目标

修复项目模板填充后正文 VML 文本框丢失、附件区域空白页，以及 `data_summary` 缺失值渲染为空的问题，使生成文档与甲方认可模板保持结构和分页一致。

## 验收标准

- [x] 生成 DOCX 的正文保留 `w:pict`、`v:shape`、`v:textbox`、`w:txbxContent`，并替换其中占位符。
- [x] 附件摘要、附件1、附件2、附件3分别独占一页，且不产生空白页。
- [x] `data_summary` 缺失、`null`、空字符串、纯空格时均渲染为“即时通讯、手机信息”；正常值原样保留（去除首尾空格）。
- [x] 模板可由脚本从甲方认可 DOCX 重新生成，且不使用奇数页/偶数页分节符。
- [x] 通过后端相关测试、架构/类型门控、DOCX ZIP/XML 校验和 Word 实际分页验证。
- [x] 甲方人工打开最终 DOCX 进行视觉复测并确认版式、图片清晰度和可读性。

## 设计说明

- VML 文本框是正文段落中的 `w:pict` 子树，不能删除其宿主段落；只在该 XML 子树内部替换占位符。
- 附件摘要、附件1和附件3使用标题段落开头的普通 `w:br w:type="page"`；附件2沿用附件1表格后的模板自然分页，移除所有 `w:pageBreakBefore`，避免表格/空段落与分页属性叠加生成空白页。
- 默认值在模板填充入口统一规范化，确保预览编辑后的报告对象和解析结果都能得到一致的最终渲染值。
- 数据导航分类不是用户输入的“数据摘要”；解析结果和前端展示默认使用固定值，用户明确输入的非空摘要仍保留，导出前后再次做空值兜底。
- 图片必须在页面可用高度内按原比例缩放；附件3只保留一个普通分页点，并清理图片插入产生的无意义空段落，避免图片后的内容把不可见段落推成空白页。
