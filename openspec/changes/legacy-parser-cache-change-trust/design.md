## Context

当前解析缓存有两条输入校验路径：Legacy动态依赖使用`selected_files_content_fingerprint`及进程内digest缓存；新版报告输入快照使用依赖记录、候选目录成员和元数据优先校验。两条路径都可能在大小、stat时间和文件身份未变化时跳过内容读取，因此同路径同大小覆盖可能返回旧`InspectionReport`。

Spike证明了该缺口，并证明Windows NTFS的per-file USN令牌可以在恢复原stat元数据后仍识别原地覆盖。13,500个合成依赖文件上，当前Python路径的热校验约20–23秒；USN令牌建立/校验约1.0–1.1秒；单文件变化只重读一个509字节文件；状态不可信时完整读取约1.65秒。

这些数字不是同一调用链：真实Parser约366ms、预览API约450–492ms是完整服务调用，文件数量和缓存状态不同；Spike直接调用文件指纹、USN IOCTL或内容读取。后续验收必须使用同一合成目录、同一Parser/API入口，并分别记录冷启动、进程内热命中、重启后首次复核和单文件变化。

## Goals / Non-Goals

**Goals:**

- 同路径、同大小、stat不变的内容替换不得复用旧digest或旧解析结果。
- 在Windows NTFS且变化令牌可信时，不无条件重读所有依赖文件。
- 任何无法证明未变化的状态都安全降级为完整内容digest复核。
- Legacy动态依赖路径和输入快照路径共享同一可信度语义。
- 处理目录成员变化、文件身份变化、读取失败和读取期间变化。
- 明确进程内缓存、磁盘解析缓存及服务重启后的信任边界。
- 保持解析失败不发布旧结果，且不改变正式归档和Word安全门控。

**Non-Goals:**

- 不建设通用文件监听平台，不实现断点续读或跨机器缓存。
- 不修改ArchiveContext、WinRAR、Manifest、Word、正式模板、Shadow或Canonical。
- 首版不持久化USN游标；只有后续证明重启后性能需要时才增加令牌字段和格式迁移。

## Decisions

### 1. 使用统一的变化可信度接口

解析缓存只依赖一个内部Provider，返回以下状态：

- `trusted_unchanged`：变化令牌和文件身份均可验证，允许复用digest。
- `changed`：文件身份、USN或目录成员发生变化，缓存失效。
- `untrusted`：平台、Journal、权限、路径、读取前后状态或API结果无法证明未变化，必须内容复核。

Provider返回不透明的原因码，不返回绝对路径。Legacy指纹函数和输入快照校验均通过该接口判断，禁止各自重新实现stat-only逻辑。

### 2. Windows NTFS优先使用per-file USN令牌

在受支持的本地NTFS卷上，适配层使用Win32文件句柄读取当前文件USN记录，并结合卷身份、Journal ID、File Reference Number和USN组成内部令牌。命中时必须重新取得当前令牌；令牌相同才允许复用digest。

Journal ID变化、当前USN超出可验证范围、USN读取失败、权限不足、文件系统不支持或卷状态不明，均返回`untrusted`，不得继续信任旧digest。适配层优先使用Python标准运行时的Win32调用能力，不引入甲方额外安装组件。

**备选：仅stat元数据。** 拒绝，因为Spike已构造出内容改变而stat元组完全相同的旧digest复用。

**备选：FileSystemWatcher。** 仅可作为进程内失效优化，不作为正确性证明。它不回放重启前事件，且存在监听空窗、缓冲区溢出和事件处理延迟；通知缺失必须转入内容复核。

**备选：每次完整读取。** 作为所有不可信状态的安全降级，不作为可信NTFS热命中的默认路径。

### 3. 目录成员变化单独校验

候选目录每次读取成员集合并形成排序后的相对路径/类型摘要；新增、删除、类型改变或候选目录消失立即使缓存失效。动态依赖列表与缓存快照的成员集合必须一致。成员摘要不保存绝对路径，也不通过读取全部附件内容实现。

### 4. TOCTOU采用前后令牌确认

完整内容复核时记录读取前令牌，流式读取内容，再记录读取后令牌。前后令牌、大小、文件身份不一致时不发布digest、不写入解析缓存、不返回解析结果，并返回可重试的`input_changed_during_read`状态；禁止用sleep或随机重试掩盖持续变化。

可信热命中在返回前再次确认令牌仍与决策时一致。无法完成确认时进入内容复核。验证点之后发生的外部修改由下一次请求的USN变化检测发现；不引入阻塞式长期文件锁。

### 5. 区分三类缓存信任边界

- **进程内digest缓存：** 只保存内部路径键、digest和令牌，不向API暴露。进程重启后全部视为未建立可信状态。
- **磁盘解析缓存：** 仍保存Legacy `InspectionReport`和源指纹，不保存绝对路径。没有新令牌字段的旧记录只能经过完整内容复核后迁移，不能直接获得快速命中资格。
- **服务重启首次使用：** 首版不持久化USN令牌；首次使用磁盘缓存必须完整复核依赖内容，成功后在当前进程建立令牌状态。这样避免为尚不存在的重启性能需求增加持久化复杂度。

缓存格式增加独立的`input_trust_schema`版本。缺失或过低版本的记录不直接删除，先按安全路径完整验证；验证成功后按新格式重写。损坏、载荷不完整或Legacy DTO校验失败时按缓存miss处理。

### 6. 失败和降级语义

降级只增加读取和校验成本，不阻止正常解析。安全降级原因包括：非NTFS、网络/移动/云占位来源、USN不可用、Journal重建或断档、权限不足、文件不存在、文件类型变化、读前后令牌不同以及API异常。若完整复核本身失败，解析失败并保留原有错误边界；绝不返回旧缓存作为成功结果。

### 7. 性能验收使用统一指标

每次基准必须记录实际依赖文件数、stat次数、令牌查询次数、读取文件数、读取字节数、digest重算数、解析构建次数和总耗时。固定矩阵包括：

1. 同一进程首次解析；
2. 同一进程未变化热命中；
3. 服务重启后首次复核；
4. 单文件同大小变化；
5. 成员新增/删除；
6. USN不可信时完整复核。

验收比较的是同一Parser/API调用链和同一合成输入，而不是把直接IOCTL耗时与完整预览API耗时混比。缓存热命中不得完整读取依赖内容；不可信状态必须证明内容复核确实发生。

### 8. Archive和正式输出隔离

本变更只决定解析输入缓存是否可复用。正式ArchiveContext、完整inventory、WinRAR、Manifest和Word仍按现有正式门控执行；解析缓存不得提供RAR、Manifest或Word的可信替代物。Legacy仍是唯一正式输出，Canonical和Shadow不参与。

## Risks / Trade-offs

- **[USN不可用导致性能下降]** → 继续允许解析，但转入完整内容复核；记录不透明原因码和可聚合指标，不能静默复用旧结果。
- **[Win32 API在EXE打包后行为不同]** → 使用最终PyInstaller/EXE执行普通文件、权限不足、非支持来源和API失败矩阵；将Windows适配放在惰性加载的后端Repository层。
- **[Journal重建或卷身份变化]** → 比较Journal ID/卷身份并视为`untrusted`；不尝试自动接管旧令牌。
- **[文件在校验期间持续变化]** → 前后令牌不一致即不发布结果；由上层返回明确的输入变化失败并允许用户重新解析。
- **[旧缓存格式被错误信任]** → 缺失`input_trust_schema`时强制完整内容复核，成功后再迁移。
- **[13,500文件的令牌查询仍有开销]** → 以依赖文件数量和令牌查询次数作为性能门控；不引入未经证明的抽样、大小估算或输出文件增长假进度。
- **[回滚到旧stat-only代码重新引入缺口]** → 新版本提供关闭快速令牌路径的开关，关闭后仍执行完整内容复核；若必须回退旧二进制，先隔离/失效解析缓存，不删除RAR、Manifest或Word。

## Migration Plan

1. 先实现纯Provider合同和模拟Provider测试，不改变正式解析入口。
2. 实现Windows NTFS适配及不可信降级，完成原地覆盖、替换、重建、权限和TOCTOU测试。
3. 接入Legacy动态依赖和输入快照两条缓存路径，增加缓存格式版本和旧记录安全迁移。
4. 在合成13,000+依赖、真实等价解析链路和最终EXE中完成性能及兼容验收。
5. 以默认快速令牌、可配置安全降级开关发布；若发现部署兼容问题，关闭快速路径保留完整内容复核。

回滚不执行历史改写，不触碰正式归档文件。新代码回滚优先关闭快速令牌路径；只有在隔离解析缓存并确认不再复用旧记录后才允许回退旧二进制。

## Open Questions

- 最终部署账户是否能在所有甲方目标机器上读取普通授权文件的USN记录，需用打包EXE验证。
- 甲方是否要求服务重启后仍保持大型解析缓存的亚秒级命中；在该需求明确前不持久化USN令牌。
- 是否需要把USN可信度诊断接入工作台，当前仅要求后端可聚合、API不泄露路径。
