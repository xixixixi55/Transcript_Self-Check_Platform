## MODIFIED Requirements

### Requirement: 受控桌面启动生命周期

`文枢.exe` MUST 实施单实例控制、启动后端、等待有界健康检查并优先打开 WebView2 独立桌面窗口；WebView2、CLR 或桌面宿主不可用时 MUST 关闭失败宿主、使用新的启动秘密有界重启一次所属后端并回退到默认浏览器。退出、启动失败和回退重启时 MUST 清理其拥有的窗口、托盘和后端进程；不得允许同一用户数据根被两个文枢版本同时运行。

#### Scenario: 正常启动

- **WHEN** 运行时资源完整、后端在时限内返回就绪且 WebView2 桌面宿主可用
- **THEN** 启动器只打开一个文枢独立桌面窗口并通过系统托盘保持后端运行
- **AND** 系统不得同时打开默认浏览器中的第二份文枢页面
- **AND** 正常运行期间不得保留要求用户一直保留的阻塞式控制台窗口

#### Scenario: 桌面宿主失败时回退浏览器

- **WHEN** WebView2、CLR、pythonnet 或最终应用页未在时限内成功初始化
- **THEN** 启动器关闭失败宿主和旧托盘、终止原所属后端，并使用新启动秘密有界重启一次后端后打开一个默认浏览器入口
- **AND** 原启动秘密无论是否已经消费都不得用于回退引导或写入错误日志

#### Scenario: 托盘重新打开与退出

- **WHEN** 文枢已启动且用户通过托盘菜单选择打开或退出
- **THEN** “打开文枢”恢复当前活动的同一个 WebView2 窗口，或在浏览器回退模式下使用现有桌面会话重新打开应用地址，不启动第二个后端
- **AND** 只有“退出文枢”才移除托盘图标、关闭当前宿主、终止启动器拥有的后端进程树并释放单实例锁

#### Scenario: 重复启动

- **WHEN** 同一用户数据根已经由一个文枢实例持有部署锁
- **THEN** 后续启动器不得启动第二个后端，并将用户引导到现有实例或显示明确提示

#### Scenario: 后端启动失败

- **WHEN** 后端退出或在健康检查时限内未就绪
- **THEN** 启动器终止其拥有的进程树、保留脱敏日志并显示启动失败提示

#### Scenario: 桌面窗口触发本机文件夹选择

- **WHEN** 用户从文枢 WebView2 窗口或浏览器回退页面选择报告目录或统一导出目录
- **THEN** 原生文件夹选择框以触发操作时的前台窗口为 owner 并显示在当前宿主之前
- **AND** 无法取得前台 owner 时使用隐藏本机 owner 与置顶兜底，同时记录可诊断但不泄露路径的状态
