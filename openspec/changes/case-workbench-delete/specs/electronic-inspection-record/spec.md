# 规格增量：案件工作台删除

> 基准 Spec：`openspec/specs/electronic-inspection-record/spec.md`
> 变更类型：MODIFIED（案件工作台删除交互与 API）

## MODIFIED: CAP-011 — 案件工作台删除

### REQ-029：案件删除必须经过确认并由服务端真实执行

案件工作台 MUST 提供案件删除操作。删除操作 MUST 先经过用户确认；取消确认不得发送删除请求。确认后 MUST 调用服务端删除 API，服务端成功后该案件不再出现在案件工作台列表中。

#### Scenario: 确认归档案件并执行既有删除能力

- WHEN 用户点击案件卡片的“归档案件”操作
- THEN 页面弹出标题为“确认归档该案件？”的确认提示
- AND 已导出案件的提示明确说明删除后案件将从工作台移除，已导出到目标目录的文件不会被删除
- WHEN 用户点击“确认归档”
- THEN 前端调用对应案件的 DELETE API
- AND 服务端真实删除该案件的工作台业务记录
- AND 删除成功后工作台刷新列表，不再显示该案件

#### Scenario: 取消归档案件

- WHEN 归档确认提示已经打开
- AND 用户点击“取消”或关闭提示
- THEN 不调用删除 API
- AND 案件、草稿、来源和工作台列表保持不变

#### Scenario: 删除入口按案件阶段确定权重

- WHEN 案件已导出
- THEN 卡片直接显示可见的“归档案件”推荐操作，更多菜单不重复显示该操作
- AND 更多菜单保留“打开案件”和“再次导出”低频能力
- WHEN 案件尚未导出且允许删除
- THEN “归档案件”作为低权重操作收纳在更多菜单，不与当前阶段推荐操作竞争
- AND 任一入口均进入同一确认流程

#### Scenario: 所有案件状态复用统一删除能力

- WHEN 案件处于任意状态，包括已导出
- THEN 卡片按当前阶段展示删除入口，且只调用同一删除回调、确认弹窗和 DELETE API
- AND “更多操作”菜单不显示“彻底删除”
- AND 用户确认后复用相同的平台受控产物清理语义

#### Scenario: 用户确认后任意案件状态均可删除

- WHEN 用户确认归档案件
- AND 案件处于解析中、解析失败、归档中、归档中断、归档完成、正式导出、清理中或已完成清理等任一状态
- THEN 服务端均执行删除，不因任务、租约、工作状态、清理流程或正式产物存在而拒绝
- AND 删除请求仍只接受服务端解析出的案件标识，不接受客户端提交的路径、表名或文件清单

#### Scenario: 删除成功后的数据范围

- WHEN 服务端执行确认后的案件删除
- THEN 在同一事务中删除该部署实例下案件的草稿、来源、任务、租约、附件引用、归档工作记录、保留投影和案件壳
- AND 删除平台受控的归档压缩目录及其中产物删除后留下的空案件上级目录、Manifest 索引记录、正式 Word 文件、归档快照、临时文件和案件图片
- AND 删除案件绑定的 `.inputs`、`.i` 或 `.t` 受控目录中的归档快照、`.copying` 临时目录及其 owner marker
- AND 仅删除确认案件对应且为空的上级目录；包含其他案件或其他文件的目录必须保留
- AND 不删除案件来源目录等不由平台拥有的外部文件
- AND 服务端校验所有物理删除目标仍位于对应平台受控根目录内，不允许越界路径
- AND 不暴露数据库表名、路径、租约令牌或内部错误详情
