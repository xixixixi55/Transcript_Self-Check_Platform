### 核心产出

1. **美亚 HTML 报告解析器** — 支持 FL-901V5 标准格式，自动提取案件信息、设备详情、取证工具版本、数据分类统计
2. **Web 预览编辑** — 结构化表单渲染完整笔录，全文可编辑，硬件设备下拉选择
3. **RAR 压缩 + MD5** — 上传后自动压缩报告目录为 RAR，Python hashlib 计算 MD5（已验证与标准工具一致）
4. **officecli .docx 生成** — create + batch 方式从零构建标准格式检查笔录
5. **解析缓存** — 首次解析后缓存 JSON，重复请求直接返回
6. **硬件设备管理** — CRUD 页面 + 生成时下拉选择
7. **检材照片上传** — 支持多选上传，导出时嵌入 .docx 附件区域

## 遇到的问题

### 问题 1: officecli 不支持 .doc 格式
- 现象：首次读取用户提供的模板失败
- 根因：文件是旧版 .doc 格式，officecli 仅支持 .docx
- 修复：用户用 Word 另存为 .docx 后成功读取

### 问题 2: Python f-string 中文引号冲突
- 现象：document_builder_service.py 语法错误
- 根因：f-string 中的中文双引号 " " 被解析为字符串边界
- 修复：改用字符串拼接 `"text" + var + "text"` 替代 f-string

### 问题 3: 前端测试超时
- 现象：组件 import 测试因 Ant Design 加载慢超时
- 根因：动态 import 触发完整 Ant Design 初始化
- 修复：添加 vi.mock 模拟 antd 组件，1 秒内完成

## 沉淀的经验

1. **先看实际文档再设计** — 用户提供的脱敏 docx 和 HTML 报告是理解需求的最佳途径，不能仅凭描述猜测
2. **officecli 是核心工具** — 文档查看、格式分析、内容生成都依赖它，确保版本和路径正确
3. **中文路径处理** — Windows + Git Bash 环境下中文路径容易出问题，Python subprocess 比 bash 更可靠
4. **spec 先行** — 用户明确要求先更新 spec 再改代码，这是正确的开发流程
