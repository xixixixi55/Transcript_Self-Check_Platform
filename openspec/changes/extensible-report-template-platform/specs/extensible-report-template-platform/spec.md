# OpenSpec 差异：extensible-report-template-platform

本 delta 为 `spec-driven` CLI 提供能力入口；完整的阶段边界、模型字段、场景和兼容约束见本变更根目录的 [`spec.md`](../../spec.md)。本文件不复制根规范，避免两份需求文本发生漂移。

## ADDED Requirements

### Requirement: 第一阶段审核与导出门控具有固定业务边界

阶段一 MUST 只允许最终检材类型 `phone`/`tablet`，允许报告明确类型自动预选，无法可靠判断时由审核页面确认；不得仅根据 IMEI 推断类型。主取证软件无法可靠识别时允许审核页面分别编辑名称和版本，但确认前不得正式导出。WinRAR 缺失或不可调用时允许上传、解析和编辑，禁止自动压缩、禁止最终正式导出、不生成 `ArchiveManifest`，且不降级 ZIP。0 张图片不生成附件二页面，正偶数图片按页面计划生成，奇数图片阻止导出；附件二缺失不重排附件三编号。人员快照按用户选择顺序一人一行；附件一每页最多三条分卷并从前向后优先填满，最后一个数据页少于三卷时在最后一卷后生成“以下空白”和所需普通空白补位行以补足三个分卷槽位，恰好三卷时不生成第四个补位行，再于页面底部承载不可拆分的人员框，不得生成签名独立页。SHA-256 的64位摘要保持16磅字号、移除模板空段落并以无重叠字符宽度适配，分页规则与 MD5 一致。`shadow` 不调用 WinRAR、不执行真实重复压缩、不产生第二份正式文书。

#### Scenario: 第一阶段阻塞项不妨碍审核编辑

- **WHEN** 检材类型、主软件、图片数量或 WinRAR 存在未解决阻断项
- **THEN** 用户仍可上传、解析、审核、保存和编辑中间结果
- **AND** 统一导出门控返回明确阻断代码和可操作提示
- **AND** 最终正式导出被拒绝直到阻断项清除

### Requirement: 可扩展管道分阶段并受门控

系统 MUST 按根 `spec.md` 定义的三阶段边界交付：阶段一实现当前报告 + `current-template-v1` 的确定性能力，主迁移方向为 `ReportAdapter → CanonicalInspectionCase → InspectionReport → 现有前端和导出`；阶段二只在用户确认字段候选后保存/复用 `ReportProfile`；阶段三只在用户可视化确认/修正后启用 `TemplateProfile`。`InspectionReport → CanonicalInspectionCase` 仅用于旧 DTO 输入和历史迁移，不承担 canonical 的完整回填。任何阶段的规划、模板资产、Profile 或导出门控失败都 MUST 阻止错误结果提交，并保留可回滚的旧路径。

#### Scenario: 第一阶段已准备实现

- **WHEN** 变更包被 OpenSpec 校验并进入实现阶段
- **THEN** 阶段一的 parser compatibility、canonical model、archive/page plan、`current-template-v1` renderer、测试和人工验收任务可独立执行，阶段二/三不会被隐式宣称已完成

#### Scenario: 不静默启用后续阶段自动化

- **WHEN** 报告结构或模板没有已确认的 Profile
- **THEN** 系统展示候选/推荐及来源和置信信息，要求用户确认或修正；在确认前不得静默解析、套用或导出

### Requirement: 陌生报告发现与 ReportProfile 复用安全隔离于内置适配器

系统 MUST 先执行内置适配器唯一匹配；仅在结果为 `REPORT_ADAPTER_NOT_FOUND` 时才可启动陌生结构发现，适配器冲突或已知格式不得进入发现链路。结构发现 MUST 是只读、非执行、有界的，仅检查允许深度和数量内的 JSON/JSONP 元数据候选，不执行 HTML、JavaScript、附件、媒体或工具程序。发现结果 MUST 只形成待确认候选；用户确认前不得创建 `InspectionReport`、案件草稿或正式导出。确认后的 `ReportProfile` MUST 版本化持久化，且不得保存案件字段原值；后续仅在已确认 Profile 的结构指纹精确命中时复用，并统一投影到 `CanonicalInspectionCase`。

#### Scenario: 已知格式不承担陌生发现成本

- **WHEN** 输入命中美亚 legacy、美亚 new、平航 v1 或奇安信网页版 v1 内置适配器
- **THEN** 系统直接使用内置适配器构建快照和 Canonical 投影
- **AND** 不扫描未知元数据候选、不读取 ReportProfile 仓储，原输出合同保持不变

#### Scenario: 首次陌生结构只生成待确认候选

- **WHEN** 输入未命中任何内置适配器且在发现预算内包含可安全读取的 JSON/JSONP 元数据
- **THEN** 系统返回结构指纹、字段候选、来源相对路径、数据路径、类型证据和置信度
- **AND** 不持久化字段原值，不生成案件草稿或正式报告
- **AND** 用户必须显式选择并确认字段映射后才保存 confirmed Profile

#### Scenario: 已确认结构复用并对变体安全失败

- **WHEN** 后续报告结构指纹精确命中 confirmed Profile
- **THEN** 系统按版本化映射提取字段并统一投影到 Canonical 审核链路
- **AND** 结构变化、必要字段缺失、路径类型变化、读取预算超限或 Profile 非 confirmed 时停止复用并重新进入候选确认，不静默套用旧映射

#### Scenario: 发现范围与读取身份保持安全稳定

- **WHEN** 陌生报告包含附件、媒体、明细、工具、资源或编号数据子树，或候选文件/祖先在枚举后被替换、增长或变成链接
- **THEN** 发现器不进入被排除子树，其内容不参与候选、预览、结构指纹或来源指纹
- **AND** 被排除的目录和不支持的文件不消耗相关候选目录项预算；系统以独立且更高的扫描总量上限防止无界枚举
- **AND** 单个超过候选读取上限的元数据文件被跳过，不得因此否定同一报告内其他处于预算内的安全候选
- **AND** 每个候选以枚举身份、受控句柄和流式字节上限读取；身份、大小、时间或祖先链变化时安全失败，不读取替换后的外部内容
- **AND** 重复 JSON 属性及 `NaN`、`Infinity`、`-Infinity` 等非有限数值不得进入候选或 Profile

#### Scenario: 确认映射保持字段和版本身份

- **WHEN** 用户确认案件标量字段和多个检材字段，或两个会话竞争确认同一结构
- **THEN** 案件标量必须唯一命中；检材字段必须来自同一来源文件和集合锚点，并具有相同索引集合、基数及同质值类型
- **AND** 同结构仅允许名称与规范化映射完全一致的幂等确认；不同名称或映射返回稳定冲突且不覆盖先前 Profile
- **AND** 案件来源记录 Profile ID 与版本，后续解析始终读取该精确版本，不因新版本出现而切换到 latest

### Requirement: 已确认平航 v1 报告使用安全的内置适配器

系统 MUST 通过版本化内置适配器 `pinghang-mobile-multipath-v1` 支持当前已确认结构的平航手机多路取证离线网页报告。识别 MUST 联合使用入口、导航、版本化报告页锚点、ViewData 固定赋值前缀、页面类型和字段标签，不得只依赖目录名、案件名或样本文件编号。报告信息页 MUST 由 v1 `0_1.json` 锚点加结构/标签校验确认，案件页 MUST 由导航“案件信息”节点定位，材料页 MUST 由 `DeviceInfo` 节点定位；同一顶层设备作用域内唯一显示名为“机主信息”的 Table MAY 作为该材料的持有人页，并且只能将明确“用户姓名”字段映射到 `holder_name`。未选中的 ViewData 不得枚举或读取。报告内 JavaScript、工具程序和附件内容 MUST NOT 被执行；被选 `.json` 后缀 JSONP 页面只能按受限数据字面量读取。报告总容量和非核心页面数量不得阻止案件初始化；未知变体、适配器冲突、导航/材料/机主信息配对歧义和重复检材编号 MUST 阻止正式导出，不得静默回退。

#### Scenario: 当前平航结构进入现有审核和导出链路

- **WHEN** 用户选择命中全部 v1 结构签名的平航报告目录
- **THEN** 系统将案件、送检人员/单位、材料、标识符、软件候选和全部材料的取证起止时间映射到 canonical/provenance，再投影现有 `InspectionReport` 供审核
- **AND** 主取证软件名称按用户确认的 v1 适配规则默认为“平航手机多路分析取证软件”并标记为 `confirmed_by_user`，版本取报告“数据取证软件版本”
- **AND** 材料页明确“数据类型”为 `Android设备`（允许大小写、全半角和空白差异）时，按用户确认的 v1 规则归类为手机并标记为 `confirmed_by_report`；该映射不适用于其他报告格式或未知类型值
- **AND** 同一顶层设备作用域内存在唯一“机主信息” Table 时，仅将其中明确的“用户姓名”映射为该检材 `holder_name`；电话号码、证件信息和其他人员字段不得作为持有人姓名
- **AND** 检查起止时间取全部材料中最早的有效取证开始时间和最晚的有效取证结束时间；任一材料时间缺失、非法或倒置时留空待审核
- **AND** 报告未明确绑定取证硬件时不得套用美亚硬件默认值
- **AND** 正式 Word 继续使用当前 legacy renderer、最终 Manifest、附件计划和已选模板，不因此切换全局 canonical 模式

#### Scenario: 平航外层多报告包合并为一个多检材案件

- **WHEN** 用户选择的外层目录包含两个或更多直接子目录，并且每个候选子目录都命中受支持的平航 v1 单报告结构
- **THEN** 系统使用版本化的平航多包布局适配身份，逐包复用现有平航 v1 安全解析，将全部材料合并到一个请求级快照和案件草稿
- **AND** 外层只枚举直接子目录，最多接受 256 个候选报告包，不递归发现报告、不读取非核心 ViewData、附件、媒体或工具程序
- **AND** 各子报告的案件事实和主软件事实必须一致，检材编号必须在全部子报告间唯一；冲突、重复、损坏或不受支持的候选报告包使整个输入安全失败，不产生部分案件
- **AND** 合并后的材料按检材编号自然顺序稳定排列，字段来源和核心依赖使用相对于外层来源根的子目录路径，来源登记、复验和正式归档继续绑定用户选择的外层目录
- **AND** 现有单报告 `pinghang-mobile-multipath-v1` 身份、版本、读取范围和输出保持不变

#### Scenario: 提取内容不冒充检材照片

- **WHEN** 平航目录包含 `附件/图片文件`、默认设备图或其他被检设备内容
- **THEN** 系统不自动将其写入附件二照片引用或材料照片分组，附件二继续只消费用户显式上传和绑定的检材照片

#### Scenario: 不可信 JSONP 安全失败

- **WHEN** 被选核心 ViewData 或导航包含非法赋值、额外可执行语句、超限内容、路径越界或无法唯一确定的结构
- **THEN** 系统不执行报告内容并返回脱敏稳定错误，在问题解决前阻止正式导出

#### Scenario: 超大报告快速初始化

- **WHEN** 平航报告包含大量非核心 ViewData、附件或媒体内容，但导航和被选核心元数据满足 v1 合同
- **THEN** 系统只读取入口、导航、报告信息页、案件信息页、导航选中的材料页及与材料作用域唯一配对的机主信息页
- **AND** 导航使用独立于普通核心页的有界读取预算，合法导航超过普通核心页预算时不被误判为不支持
- **AND** 非核心页面数量、编码差异和报告总容量不线性增加案件事实解析量，也不成为案件初始化上限

#### Scenario: 轻量来源复验和解析依赖复用

- **WHEN** 系统解析或复验已识别的平航 v1 报告
- **THEN** 仅消费导航选中的核心依赖，复验使用这些依赖的大小、修改时间、文件身份及适配器版本，不额外扫描媒体或重读核心内容计算哈希
- **AND** 解析直接复用本次已读取的快照及其依赖指纹，不为适配探测和解析重复读取核心文件；不同依赖指纹不得加入同一个执行中任务
- **AND** 常规核心文件变化使来源需要重新选择；来源复验不承诺识别刻意保留文件元数据的内容改写

### Requirement: 已确认奇安信网页版报告 v1 使用安全的内置适配器

系统 MUST 通过版本化内置适配器 `qianxin-web-report-v1` 支持当前已确认结构的奇安信网页版离线报告。识别 MUST 联合使用根入口 HTML、`data/data_report_profile.json`、`data/data_navigation.json`、一个或多个 `data/data_package_profile_<index>.json`、固定 `static.report.context.<filename-stem>` 赋值和载荷字段签名，不得依赖案件目录名或原始样本值。适配器 MUST 只把这些根级元数据文件作为解析依赖，不递归读取编号数据目录、`files`、`public` 或媒体内容，不执行 HTML、JavaScript、附件或工具程序。非法赋值、额外语句、重复 JSON 属性、超限元数据、重复包索引或适配器并列匹配 MUST 安全失败。

#### Scenario: 奇安信 v1 进入统一 Canonical 审核链路

- **WHEN** 用户选择命中全部 v1 结构签名的奇安信网页版报告目录
- **THEN** 系统将案件名称/编号、送检人员/单位、案件与报告时间、每个 package profile 的检材事实、设备名称/型号、持有人、IMEI1/IMEI2/序列号、提取与解析时间及报告绑定的主软件名称/版本映射到 `CanonicalInspectionCase` 和字段来源，再投影现有 `InspectionReport`
- **AND** 多检材按 package profile 数字索引稳定排序；源报告缺少检材编号时业务字段保持为空，仅使用稳定技术材料 ID，禁止把文件索引写入 `evidence_number` 或文书正文冒充检材编号
- **AND** 检查时间取全部材料中最早的有效提取时间至最晚的有效解析时间；任一材料时间缺失、非法或倒置时留空待审核
- **AND** `source.name` 与 `source.appVersion` 作为报告明确提供的主软件名称和版本并标记为 `confirmed_by_report`
- **AND** 仅有 `检材平台=Android` 时不得自动断言材料一定是手机；类型保持待确认，直到报告提供无歧义类型或用户审核确认
- **AND** 报告未提供取证硬件时保持为空，不套用美亚硬件默认值；正式 Word 继续走现有兼容 DTO、导出门控和 legacy renderer

#### Scenario: 大体量明细和媒体不进入案件初始化

- **WHEN** 奇安信报告包含大量编号数据目录、图片、音视频、通讯录或其他提取内容
- **THEN** 适配器只枚举 `data` 根级元数据文件并读取报告、导航和 package profile，不递归扫描或读取明细及媒体
- **AND** 根入口 HTML 与导航分别使用独立的 64 MiB 有界读取预算，合法入口超过旧 4 MiB 时不被误判为不支持
- **AND** 报告总体积和非核心文件数量不线性增加案件事实解析量，也不把提取图片自动绑定为附件二照片

### Requirement: 内置模板清理保留带版本导出

内置模板清理 MUST 通过新模板版本交付。清理后的版本 MUST 删除全部批注结构和附件二示例媒体，同时保留动态图片区域锚点、VML、分页、表格与上传图片渲染能力；旧版本资产 MUST 保留供既有案件按原模板引用重导出，并作为已退役历史资产从模板管理列表和新案件可选列表隐藏，禁止设为默认或作为编辑源。

当前内置版本 MUST 以 A4 页面中心为基准居中可见主标题和首页/页脚粗横线，并保持结构标题的层级缩进：“一、绪论”“二、检查”略突出于二级标题，“（三）检查过程”“（四）检查结果”与其他二级标题对齐。该修正 MUST 发布为新的不可变版本，不得覆盖旧模板字节或既有案件引用。

#### Scenario: 从先前内置模板升级

- **WHEN** 部署升级且当前默认值仍指向旧内置模板
- **THEN** 系统将后续新案件的默认模板迁移到清理后的新版本
- **AND** 既有案件的退役内置模板引用迁移到新版本，用户选择的其他默认模板不被覆盖
- **AND** 旧内置版本不出现在模板管理列表或新案件可选列表中，管理接口拒绝将其重新设为默认
- **AND** 旧内置版本资产不再分发，既有案件按迁移后的当前版本继续导出

#### Scenario: 模板管理只保留最新内置版本

- **WHEN** 用户打开笔录模版管理页且注册表同时包含当前与历史内置版本
- **THEN** 管理列表只展示最新内置版本，不展示已退役历史内置版本
- **AND** 启动迁移清理历史内置注册记录并将其案件引用改写为当前版本，不影响自定义模板

### Requirement: 当前内置模板是唯一分发的内置资产

系统 MUST 只随程序分发当前 `word_templates/template.docx` 内置模板，不再分发 1.0.0～1.0.2 退役 DOCX 或依赖真实案件内容的一次性模板创建脚本。当前模板 MUST 清除人员、工作站和 WPS 用户标识等不可见元数据；隐私净化不得改变正文、模板固定单位文案、页眉页脚、样式、表格、VML、分页、图片区域或最终 Word 的可见业务输出。

#### Scenario: 净化元数据但保持 Word 渲染不变

- **WHEN** 当前内置模板执行仓库隐私净化
- **THEN** 核心属性使用通用系统身份，自定义属性及 WPS `docVars` 被删除
- **AND** 所有渲染相关 OOXML 部件与净化前基线逐字节一致
- **AND** 使用同一报告输入生成的 Word 可见文字、页数、分页、表格、VML 和图片布局保持一致

#### Scenario: 退役内置引用收敛到当前模板

- **WHEN** 部署数据仍包含 1.0.0～1.0.3 的内置默认值或案件模板引用
- **THEN** 启动迁移将这些引用幂等更新为当前内置版本
- **AND** 自定义模板引用保持不变

#### Scenario: Word 原生布局锚点保持视觉居中

- **WHEN** 当前内置模板由 Microsoft Word 原生渲染
- **THEN** 主标题可见字形中心、首页文号下方粗横线和各页页脚上方粗横线均与页面中心一致
- **AND** 结构标题保持一级略突出、同级对齐的缩进层次
- **AND** 页数、分页、表格列宽、VML 文本框、页眉和页脚内容保持不变

### Requirement: 模板上传标识由系统管理且显示名称是可编辑元数据

已审核模板的显示名称 MUST 可由用户在模板管理页单独修改。重命名只更新展示元数据，MUST NOT 改写模板 ID、版本、DOCX 资产、指纹、校验规则、审批记录、默认模板状态或案件中的模板引用。名称去除首尾空白后 MUST 非空且不超过 120 个字符；非法名称 MUST 被拒绝且保留原名称。

添加模板时，用户 MUST 只需提供“命名”和 DOCX 文件，不得要求用户填写模板 ID 或版本。系统 MUST 为每次成功上传生成唯一的不透明模板 ID，并以内部初始版本 `1.0.0` 注册；生成的 ID 和版本继续用于模板不可变性、默认模板和案件引用，不得因界面精简而从内部合同移除。

#### Scenario: 上传不含技术标识字段的模板

- **WHEN** 用户在添加模板界面填写有效“命名”并选择通过结构校验的 DOCX 文件
- **THEN** 界面不显示模板 ID 或版本输入项，并仅提交名称和文件
- **AND** 系统生成唯一模板 ID 和内部初始版本 `1.0.0`，返回已审核模板并保留既有不可变版本合同

#### Scenario: 重命名已批准模板

- **WHEN** 用户在模板管理页为一个已审核模板提交有效的新名称
- **THEN** 列表显示新名称并保留该模板的 ID、版本、校验状态和默认状态
- **AND** 既有案件引用、模板资产字节、指纹和审批记录保持不变

#### Scenario: 拒绝无效模板名称

- **WHEN** 用户提交空白名称、超过 120 个字符的名称或额外未声明字段
- **THEN** 系统返回稳定安全错误，界面保留用户输入以便修正
- **AND** 已保存的模板名称和其他模板元数据均不改变

#### Scenario: 管理页标题省略冗余说明

- **WHEN** 用户进入笔录模版管理、检查人员管理或取证硬件设备管理页面
- **THEN** 页面保留标题和主要管理内容
- **AND** 不显示标题下方的说明性副文案

### Requirement: 检查人员库记录单位和职位但不含可用状态

检查人员库 MUST 维护姓名、单位、职位和警号，不再维护或展示启用/停用状态。所有未删除人员 MUST 统一出现在管理列表和案件选择入口。新增人员时四项业务字段均为必填；历史 v1 人员记录 MUST 忽略原 `enabled` 值并兼容为可用，缺少职位时以空值加载，等待用户后续补充，不得因此丢失或隐藏人员。

案件 `InspectorSnapshot` MUST 保存职位并与人员库后续修改解耦；共享默认值、Canonical/Legacy 兼容投影和正式文书 MUST 保留职位。历史快照缺少职位时继续可读，正式文本不得产生空职位对应的重复分隔符。

#### Scenario: 管理和选择检查人员

- **WHEN** 用户进入检查人员管理或案件人员选择入口
- **THEN** 系统展示所有未删除人员及姓名、单位、职位、警号
- **AND** 页面不显示状态列、启停开关或启用/停用提示

#### Scenario: 兼容原停用人员

- **WHEN** 本地人员库仍是 v1 且某条记录的 `enabled` 为 `false`
- **THEN** 系统仍返回并允许选择该人员
- **AND** 缺少职位时显示空值并允许在编辑时补充

#### Scenario: 职位随案件快照进入文书

- **WHEN** 用户选择具有职位的检查人员并保存或导出案件
- **THEN** 案件快照、兼容投影和正式文书保留该职位
- **AND** 后续修改或删除人员库记录不改写既有案件快照

### Requirement: 本地 Windows 目录选择器保留基于路径的来源合同

本地 Windows 案件工作台 MUST 提供点击式“上传报告目录/添加案件”入口。入口 MUST 由后端在本机交互桌面会话中弹出原生文件夹选择窗口；选择成功后 MUST 在同一请求内使用真实绝对路径登记既有 `SourceRecord`、创建案件壳和解析任务。浏览器 MUST NOT 上传或复制报告目录，公共响应、日志和浏览器状态 MUST NOT 暴露绝对路径；选择范围 MUST NOT 被硬编码为桌面目录。取消选择 MUST 是无副作用操作。

#### Scenario: 选择目录后直接登记并解析

- **WHEN** 用户点击工作台的上传报告目录卡片并在 Windows 原生窗口选择有效报告文件夹
- **THEN** 后端直接完成来源登记、案件壳/解析任务持久化和解析 dispatch
- **AND** 前端显示排队或解析中的案件卡片，不再要求先填写路径再点击登记按钮
- **AND** 原始目录仍由既有后端路径合同直接读取，不生成浏览器上传副本

#### Scenario: 取消或无法打开选择器

- **WHEN** 用户取消选择，或 Windows 选择器不可用/超时
- **THEN** 取消不创建任何案件数据；不可用/超时返回稳定错误和可重试状态
- **AND** 错误响应不包含绝对路径、PowerShell 命令或内部异常
