## ADDED Requirements

### Requirement: REQ-GUIDED-REVIEW-SHELL — 默认对话式审核外壳

案件审核页面 MUST 在不改变现有业务事实、保存、归档、介质映射和导出机制的前提下，默认以对话式引导视图呈现当前用户可处理事项、系统处理状态和恢复入口；现有完整审核编辑能力 MUST 保留并可按需切换。

#### Scenario: 案件审核默认只展示对话式引导外壳

- **WHEN** 用户从案件工作台打开具有可审核草稿的案件，或刷新该案件审核地址
- **THEN** 页面默认只渲染对话式引导视图，不渲染现有完整审核编辑表单
- **AND** 引导模式不渲染旧“笔录生成 / 审核编辑”页头、案件摘要、保存状态和结构摘要预览入口；这些完整编辑上下文只在用户切换到完整审核编辑后展示
- **AND** 引导视图以用户任务语言展示当前可处理事项、系统处理状态和恢复操作，不要求用户理解 `CaseDraft`、Manifest、Export Gate、revision 或分卷档位等内部术语
- **AND** 默认模式只属于当前页面展示状态，不写入报告、案件草稿、浏览器持久化或服务端
- **AND** 解析中、解析失败或尚无可审核草稿的案件继续使用现有状态和恢复入口，不伪装成可填写的对话步骤

#### Scenario: 默认聚焦当前对话且向上滚动查看历史处理轨迹

- **WHEN** 对话式引导视图存在已经完成、自动处理、正在后台处理或当前需要用户操作的事项
- **THEN** 审核工作区使用同一纵向滚动轨道，把完整历史处理轨迹置于当前对话区上方，并在首次进入、刷新或切换案件时把视口定位到当前对话起点，使默认可见区域展示完整的当前办理舞台
- **AND** 当前对话区采用紧凑 Chat 形式展示獬豸助手身份、可替换的角色占位、当前推荐事项、结构化控件和主要操作；没有用户事项时显示等待后台处理、办理完成或现有恢复入口
- **AND** 历史处理轨迹按办理顺序完整渲染已经完成的用户操作、报告自动识别与系统自动沿用的信息摘要、后台任务阶段变化和已经恢复的异常；默认位于视口上方而非折叠为摘要，用户向上滚动后查看，不重复展开完整审核表单，也不改造成逐句聊天记录或消息气泡
- **AND** 用户在报告识别检材基础上自行补充检材后，历史处理轨迹更新为当前最终已处理检材总数，并简要区分报告识别数量与用户补充数量；不得记录用户逐字输入的检材内容
- **AND** 每个当前事项先由獬豸助手使用完整、可执行的提示句说明下一步，例如“请输入文号”“请选择委托时间”或“请恢复草稿保存”，不得只显示“处理文号”等状态标签后直接呈现控件
- **AND** 当前事项在本次页面会话中完成后，当前对话区展示不含逐字输入的用户完成回执，并使用与已完成事项及下一项相关的助手承接语建立“确认结果—继续办理”的因果关系；刷新或重新进入不承诺还原该回执，不保存逐字输入或新增持久化聊天记录
- **AND** 当前页面会话最多保留最近三轮有意义的完成摘要，分别说明用户完成的事项、系统确认的作用以及下一事项的原因；每轮提供返回对应既有结构化控件修改的入口，更早轮次只折叠为完成数量，不进入案件草稿或服务端
- **AND** 当前结构化事项完成并推进，或用户从全部当前事项切换到另一个结构化事项后，本次页面会话均在助手提示与回复控件之间提供“返回上一步”入口，允许用户重新查看或修改来源步骤的既有结构化控件，并提供返回最新当前步骤的入口；来源事项尚未完成时仍可返回，图片上传等高内容不得把入口推到回复区之后；步骤导航不得回滚已保存草稿、把已完成事项重新计入待处理数量或持久化为新的业务事实
- **AND** 用户主动从一个仍待处理事项切换到另一个时，助手用当前项和来源项的业务标签说明“先处理当前项、来源项仍保留”，不得虚构来源项完成；助手消息与回复控件可用相反水平方向的短暂进入动效建立对话方向感，但不得延迟操作、伪造输入或思考，且在用户选择减少动态效果时立即降级
- **AND** 獬豸助手形象可在当前对话中使用长间隔、低幅度的呼吸动效，并在当前事项变化时点头一次；非必要循环在页面隐藏或角色离开视口时停止，用户选择减少动态效果时取消空间位移，动效不得推动布局、阻塞操作或表达虚假的业务处理进度
- **AND** 獬豸助手使用同一角色的倾听、核对、严肃提醒和完成四态表情，并只在相应状态转换时执行可中断的一次性语义动作；保存冲突、权限失效、来源或图片异常不得使用欢快动作，角色资产失败时回退为现有可访问图标且不影响操作
- **AND** 文本型当前事项继续把每次输入实时写入现有报告草稿和自动保存，但输入首个字符或后续 `change` 不得自动切换事项；只有用户按下非输入法组合态的 Enter 后才确认并推进，多行文本的 Shift+Enter 继续用于换行
- **AND** 当前对话区至少占据滚动视口的可用高度并保持当前操作和全局操作可达；用户停留当前对话时新增历史记录不得把视口推离当前锚点，用户已经上滑阅读历史时不得强制拉回当前对话
- **AND** 窄屏和浏览器缩放下继续使用历史在上、当前对话在下的单一滚动轨道，取消角色独占列和不必要的嵌套滚动，文字、结构化控件、键盘焦点与主要操作不得被裁切或遮挡

#### Scenario: 历史处理轨迹不成为新的业务事实

- **WHEN** 页面把现有案件状态投影为历史处理记录
- **THEN** 当前页面会话可以保留本次操作的展示顺序，但不得新增持久化对话消息、办理历史表或案件业务字段
- **AND** 刷新或重新进入案件时，历史处理区根据当前 CaseDraft、FieldState、生命周期、归档和介质映射等现有事实重建办理摘要，不承诺还原逐字对话、精确操作时间或已经失效的中间状态
- **AND** 历史记录只描述用户可理解的办理结果，不展示内部路径、令牌、revision、Worker、堆栈、完整错误代码或技术日志
- **AND** 用户查看较早记录时，新后台状态不得强制把滚动位置拉回底部；只有用户仍位于历史末端时才可以跟随最新记录

#### Scenario: 对话外壳只投影现有事实和现有操作

- **WHEN** 对话式引导根据当前案件生成操作卡片
- **THEN** 卡片只来自当前 `InspectionReport`、既有 `FieldState`、既有待核对派生结果、案件生命周期、归档完成投影、图片状态、来源状态、编辑租约和现有导出反馈
- **AND** 对话层不新增 RequiredAction 后端接口、数据库表、案件字段、持久化对话历史、业务必填规则、确认规则或导出门控
- **AND** 用户在卡片中的操作继续调用现有字段更新、自动保存、图片绑定、来源重选、压缩决定、介质映射和 Word 导出能力
- **AND** 卡片是否消失完全由现有事实重新派生，不单独保存“已处理”或“已完成”标记

#### Scenario: 已由报告或默认设置确定的信息不重复询问

- **WHEN** 报告解析、案件草稿初始化或笔录默认设置已经提供符合现有规则的字段值
- **THEN** 对话式引导不为这些字段生成确认卡片或机械的“确认并继续”步骤
- **AND** 已由默认设置带入且信息完整的检查人员、检查地点、检查方法和硬件设备直接沿用现有案件快照与顺序
- **AND** 已生成的文号、已确认的检材信息和主取证软件继续沿用现有值；只有既有待核对或导出反馈指出缺失、格式错误、未确认或冲突时才展示对应操作
- **AND** 用户可通过“查看已整理信息”查看摘要并主动进入修改，但查看、展开或收起摘要不得修改任何业务数据

#### Scenario: 系统处理中间结果不冒充人工问题

- **WHEN** 后台压缩、完整性校验、MD5 或 Manifest 生成仍在执行，且 RAR 文件名、文件大小、MD5、实际卷数或介质模式尚未形成最终事实
- **THEN** 对话式引导把这些内容展示为系统处理状态，不要求用户手工填写系统产出字段
- **AND** 归档状态继续使用现有 `workflow_milestone`、阶段文字、运行时间、输出字节数和检测分卷数，不把活动指标换算为 WinRAR 连续完成百分比
- **AND** 系统状态与当前可处理的用户事项分区展示，后台状态变化不得抢走或清空用户正在操作的卡片

#### Scenario: 复用现有压缩决定和介质编号机制

- **WHEN** 案件处于现有压缩时机选择状态
- **THEN** 引导视图以简明说明展示“现在开始（推荐）”和“稍后处理”，并明确稍后处理对当前办理结果的现有影响
- **AND** 两个操作继续调用现有立即/稍后压缩入口，不改变来源确认、任务创建、资源调度、重试或案件生命周期
- **WHEN** 现有归档完成投影要求补充介质编号
- **THEN** 标准分卷继续使用现有首个 `GP` 光盘编号映射，超大单卷继续使用现有唯一 `YP` 硬盘编号映射
- **AND** 引导视图不得让用户选择 4GB、22GB 或 45GB 档位，也不得改写现有容量规划、盘号 CAS 或 Manifest 事实

#### Scenario: 在引导模式和完整审核编辑之间无损切换

- **WHEN** 用户在默认引导视图点击“完整审核编辑”
- **THEN** 页面切换为现有完整审核编辑视图，并提供“返回引导模式”入口
- **AND** 两种视图共用同一个案件会话、内存草稿、自动保存、编辑租约、图片资产、归档状态和导出操作，不复制或转换业务数据
- **AND** 同一时刻只渲染当前选中的视图；完整审核编辑器不得以 CSS 隐藏方式在引导模式后台同时渲染
- **AND** 模式切换不得丢失当前已输入内容、重启归档、重复上传图片、触发额外业务确认或改变案件生命周期
- **AND** 只读、租约失效、保存失败和图片尚未绑定的现有保护语义在两种视图中保持有效

#### Scenario: 检材完整性提供图标化双向选择

- **WHEN** 引导视图要求用户确认检材信息是否完整
- **THEN** 页面在选择操作之前直接展示当前全部检材的有序清单，每项至少包含检材编号、设备名称、手机/平板类型与可提取情况；未识别到检材时明确展示空态
- **AND** 页面同时提供具有明确可访问名称和提示的“完整”与“不完整”图标操作，不以图标形状或颜色作为唯一含义
- **AND** 用户选择完整时继续调用现有检材完整性确认能力
- **AND** 用户选择不完整时保持当前对话窗口并在回复区展开既有检材编辑器，用户可使用原有“添加检材”入口手工补充检材
- **AND** 用户选择不完整后先在同一回复区选择“快捷批量补充”或“逐项编辑”，页面一次只展开所选路径；另一种方式继续作为次级入口可随时切换，不同时堆叠两套完整控件
- **AND** 对话外壳不得复制检材编辑、草稿保存、字段来源或完整性确认逻辑

#### Scenario: 不完整检材支持按行快捷批量添加

- **WHEN** 用户在检材完整性事项中选择“不完整”并使用快捷批量添加
- **THEN** 獬豸助手明确提示每个非空行只表示一项检材，格式为“设备名称手机一部（无法提取原因）检材编号”或“设备名称平板一部（无法提取原因）检材编号”，原因必须使用中文全角括号且检材编号位于行末
- **AND** 系统忽略空行并把每个合法行解析为设备名称、已由用户确认的手机或平板类型、无法提取状态、无法提取原因和检材编号，在写入案件前展示结构化预览与识别数量
- **AND** 任一非空行格式错误、批次内检材编号重复或与现有检材编号重复时，页面按行说明问题并阻止整批写入，不丢失用户原始输入
- **AND** 用户确认预览后，系统把整批检材追加到现有 `introduction.evidence_list`，不得覆盖现有检材，并继续调用同一报告更新、自动保存、字段来源和完整性确认链路
- **AND** 快捷添加完成后仍保留既有结构化检材编辑器，允许用户逐项修正或继续手工添加

#### Scenario: 快捷补录操作相邻并按既有规则一键排序

- **WHEN** 用户在不完整检材回复区填写快捷补录内容
- **THEN** 输入框下方按键盘与视觉顺序相邻展示“解析并预览”“一键排序”和既有“确认检材完整”圆形图标操作，每个图标均提供明确 Tooltip 和可访问名称，不重复显示可见按钮文字；窄屏空间不足时整组自然换行且操作仍可辨识、可聚焦
- **AND** 用户点击一键排序时，系统使用报告识别阶段相同的多段数字自然升序规则排序当前合法预览及现有检材，使 `JC1`、`JC2`、`JC10` 按该顺序排列
- **AND** 只有全部编号均可提取安全数字且数字排序键互不冲突时才执行排序；无法安全排序时保持当前相对顺序并明确说明原因
- **AND** 排序只由用户本次显式操作触发，排序后的案件数组继续作为下游权威顺序；后续普通保存不得再次自动排序或覆盖用户拖拽顺序

#### Scenario: 引导视图保留全局控制而非强制单线问答

- **WHEN** 当前同时存在多个用户可处理事项或后台任务
- **THEN** 页面在下方当前对话区推荐一个当前事项，同时以带 Tooltip 和明确可访问名称的圆形图标工具栏提供“查看全部待处理事项”“查看已整理信息”“完整审核编辑”和“返回案件列表”；当前回复或确认始终是唯一主操作，工具栏不得改为常驻文字按钮或“更多操作”菜单
- **AND** 用户可以从全部待处理事项进入任一现有字段或操作，不被强制锁定在固定的一题一页顺序中
- **AND** 页面分别表达“需要用户处理”的数量与“系统正在处理”的状态，不使用可能因异步变化产生倒退含义的固定“问题 X / Y”总进度
- **AND** 新出现的介质编号或恢复事项先进入上方历史处理区和待处理列表，在当前输入收敛后才成为下方当前对话，不突然替换用户正在编辑的内容
- **AND** 除“选择压缩时机→填写介质编号”作为正常办理的明确前置顺序外，助手不得为文号、委托时间、案件简要情况、检材、图片等其余字段采用固定题序；已由报告、默认设置或用户操作满足的事项直接从操作集中消失，但报告解析出的案件简要情况仍须在本次页面会话中以预填多行输入框提供一次人工核对和修改，确认后不重复询问
- **AND** 压缩时机属于可自由选择的现有操作，选择稍后压缩不得被重新解释为必须立即压缩，也不得通过重复提问把用户锁回立即压缩路径

#### Scenario: 正常办理先完成压缩选择与介质编号

- **WHEN** 案件没有保存、租约、来源或图片恢复事项，且处于可选择压缩时机的审核状态
- **THEN** 獬豸助手首先推荐现有“选择压缩时机”操作，不得先推荐文号、委托时间或其他普通审核字段
- **AND** 用户完成压缩时机选择后，介质编号为空或无效的情况下，助手下一步推荐填写介质编号
- **AND** 介质编号满足现有校验后，助手再从其余现有动态待办中推荐文号、委托时间等事项，不复制或改变字段校验规则
- **AND** 保存失败、编辑租约失效、来源不可用或图片未安全绑定等会阻止安全继续的恢复事项仍优先于该正常办理顺序
- **AND** 用户选择稍后压缩后可以继续填写介质编号和其他审核事项；再次立即压缩入口保留在全部待处理事项中，不得持续占用当前推荐操作

#### Scenario: 保存、租约和图片异常在引导视图中提供现有恢复操作

- **WHEN** 现有案件会话报告草稿保存失败或 revision conflict、编辑租约只读/过期/获取失败，或者图片上传、绑定或读取出现异常
- **THEN** 对话式引导以用户可理解的语言说明未完成事项、对当前输入和输出的实际影响，并把对应现有恢复操作加入当前操作集或全部待处理事项
- **AND** 草稿保存失败或冲突必须保留当前输入和待保存状态，并复用现有重试保存或加载服务端版本能力；不得只显示与真实保存结果无关的“已保存”“尚未修改”或“办理完成”状态
- **AND** 图片上传或绑定失败继续遵守既有离页保护并提供现有图片控件恢复入口；单独 Word 的图片读取超时或失败继续遵守既有非阻断容错合同，但页面必须明确提示附件2将被省略，不得静默声称图片已经进入 Word
- **AND** 恢复事项的完成仍由既有保存、租约、图片和导出事实重新派生，不新增对话层完成标记，也不改变现有 Export Gate 或两种输出合同
- **AND** 用户正在编辑其他卡片时，新出现的恢复事项先进入历史区和全部待处理事项；除非当前操作已经不可写或继续操作会丢失数据，不得突然卸载或替换用户正在输入的控件

#### Scenario: 引导模式与完整审核编辑切换后恢复可预测焦点

- **WHEN** 用户从引导视图打开完整审核编辑中的具体待核对事项
- **THEN** 页面在完整编辑器挂载后将键盘焦点移动到对应结构化控件；没有具体目标时聚焦完整编辑区的具名标题或首个可办理区域
- **WHEN** 用户从完整审核编辑返回引导模式
- **THEN** 页面在引导视图挂载后将焦点移动到当前对话的具名标题或当前操作卡片，不得因原切换按钮被卸载而把焦点遗留在不可预测位置
- **AND** “查看全部待处理事项”和“查看已整理信息”的触发器通过稳定标识与其展开区域建立可访问关系，展开、收起、键盘顺序和现有快捷键在窄屏及浏览器缩放下保持可用
- **AND** 用户展开“查看全部待处理事项”或“查看已整理信息”后，目标面板必须立即进入当前单一滚动视口的可见范围并获得可预测的键盘焦点，不要求用户继续向下滚动才能看到内容

#### Scenario: 后台归档与人工审核并行且办理终态语义分离

- **WHEN** 用户选择立即压缩且既有保存与来源确认成功
- **THEN** 助手把归档排队、压缩、完整性校验、MD5 和 Manifest 阶段展示为后台系统状态，并允许用户继续处理当前案件的其他既有待办
- **AND** `archive_queued`、`archiving`、图片上传请求返回或“已选择立即压缩”均不得被描述为笔录办理完成
- **WHEN** 用户选择稍后压缩并且当前草稿已经安全保存
- **THEN** 助手明确显示“草稿已保存并稍后处理”，允许用户继续审核或安全返回案件列表，不重复强迫选择立即压缩
- **WHEN** 单独 Word 导出成功、统一导出成功或后台归档仍在处理
- **THEN** 助手分别使用“Word 已导出”“统一导出已完成”或“后台归档处理中”的准确状态，不把不同输出合同和中间状态合并成单一“完成”终态

#### Scenario: 最终生成继续由现有保存与导出门控裁决

- **WHEN** 引导视图根据现有派生结果没有发现当前可处理的待核对事项
- **THEN** 页面可以展示“笔录已准备完成”和现有生成入口，但不得把对话层状态作为正式导出许可
- **AND** 用户点击生成后继续等待现有图片绑定和自动保存收敛，并调用现有 Word 导出或统一导出流程
- **AND** 现有 Export Gate、模板校验、归档校验或最新 revision 返回阻断时，页面以可操作的用户语言展示原有错误并返回对应现有操作，不绕过、放宽或复制门控
- **AND** 单独 Word 与统一导出的图片、归档和介质要求继续遵守各自现有合同，对话外壳不得把两种输出的条件合并成新的统一规则

#### Scenario: 对话助手保持专业、可访问且不阻断办理

- **WHEN** 引导视图展示獬豸助手、状态文案和操作卡片
- **THEN** 助手使用简洁、明确、专业、亲和且克制的办理语言，优先说明推荐操作及其影响
- **AND** 角色图像缺失、加载失败、动画关闭或用户启用减少动态效果时，全部文字、状态和操作仍保持可用
- **AND** 成功、警告、错误、只读和处理中状态不得只依赖角色表情、颜色或动画表达
- **AND** 历史处理区与当前对话区具有明确区域名称，键盘可以进入历史记录和当前控件，焦点、可访问名称、窄屏布局和现有快捷键行为保持可用
- **AND** 窄屏和浏览器缩放不得通过过小操作目标、嵌套滚动或被遮挡焦点阻止用户打开待办、执行恢复、切换模式或返回案件列表
